# 网页 JavaScript 迁移记录

日期：2026-09-28。对照版本为迁移前的 `544da884aef4d4b597ab5dfeeaa86f359c1ccd37`。

## 改了什么

网页和 Electron 现在直接执行 JavaScript。保留原来的网格候选、起点搜索、边段验证、原生像素保护、照片回退、取色、透明度和颜色后处理规则，没有调整算法阈值。Python CLI/API 的生产代码没有修改。

算法在 `web/core/`，页面只负责交互，Worker 负责文件与任务调度。PNG 通道直接解码与编码；FFT、偶数舍入和关键 float32 运算显式实现，避免语言默认行为改变格距或颜色。颜色数量和色库继续作用于缓存的不限色结果，不重新检测网格。

移除网页中的 Pyodide、NumPy/Pillow wheel、Python 标准库、`core.zip`、`bridge.py`、`build.py`、旧运行时许可证和旧浏览器测试脚本。网页没有新增第三方运行依赖。`core-manifest.json` 现在是 JS 资源清单，构建与部署用 Node；CI 使用 Python 生成参考数据，不把 Python 放进网站。

包含同一张示例图片的完整静态网站，从 **29.26 MiB 缩小到约 1.96 MiB**；开发脚本与测试不进入发布目录。

这些测试验证迁移一致性，不代表任意输入都能恢复唯一的真实网格。

| 原有 Python 回归 | 307 项通过，46.91 秒 |
| 持久 JavaScript 测试 | 77 项通过，包含下面的 49 组完整流程对照及独立数值/格式测试 |
| 完整 Python/JS 流程对照 | 49 组通过：10 张 input 实图、39 组合成/参数案例 |
| 取色与颜色处理专项对照 | 160 组通过：取色浮点数组、输出像素与相关诊断一致 |
| PNG 与 Pillow 解码对照 | 74 组通道字节一致，含透明度、合法位深、Adam7、过滤器和方向 |
| 浏览器 JPEG/EXIF/MPO/GIF/WebP | 18 个静态案例的输入和最终输出字节一致，动画正确拒绝 |
| 过程图底层预览 | 6 个案例的原图/FFT/边缘，共 18 组像素一致 |

完整流程对照要求输出和不限色原生结果的 RGBA **逐字节相同**；网格切割线、尺寸、路径选择也相同。连续浮点参数容差为 `1e-6`，例如 lastTour 的起点末位相差约 `4e-16`。这不放宽像素或切割线断言。

可重复的测试入口：

```bash
python scripts/export_web_reference.py
npm --prefix web test
cd desktop-electron
npm test
```

对照数据生成在忽略目录 `build/web-reference/`。独立测试另覆盖 FFT 的质数/混合长度、中心噪点、透明度、色库、损坏 PNG、动画拒绝、1–16 倍最近邻导出及过程图归一化。没有参考数据时，对照测试明确跳过；CI 总是先生成参考数据。

## 实际浏览器速度

环境：Windows 10.0.26200，Intel Core i9-12900H，Electron 44.4.3 / Chromium 152.0.7977.130，Node 22.22.0。本机 HTTP、没有网络限速，旧版和新版交替执行，各 3 轮，以下为中位数。未把本机网络结果当作公网下载速度。

| 指标 | 旧 Python 网页引擎 | 新 JS 引擎 |
| --- | ---: | ---: |
| 新浏览器配置中的首次 Worker 就绪 | 2.219 秒 | 0.027 秒 |
| HTTP 缓存命中后的新 Worker 就绪 | 1.948 秒 | 0.016 秒 |
| 初始化静态资源字节数（未作 HTTP 压缩） | 28,830,224 | 237,391 |

处理时间从 Worker 收到文件到返回结果，包含读取、算法、PNG 导出及按配置生成过程图；不含首次引擎初始化、选择图片和页面绘制。

| 图片 | 过程图 | 旧版 | JS |
| --- | --- | ---: | ---: |
| 1024×1024 测试输入 | 关闭 | 0.481 秒 | 0.511 秒 |
| 同上 | 开启（界面默认） | 1.753 秒 | 1.092 秒 |
| ritsu，1024×1536 | 关闭 | 0.449 秒 | 0.619 秒 |
| 同上 | 开启 | 1.021 秒 | 0.792 秒 |
| lastTour，1536×1024 | 关闭 | 0.663 秒 | 0.636 秒 |
| 同上 | 开启 | 1.203 秒 | 0.971 秒 |

这里的 1024×1024 输入来自 `input/1770467992323.jpg`，通过 Pillow 解码后保存为 PNG，尺寸和像素不变，用来隔离浏览器解码器的影响。三张图、两种过程图设置、两个引擎、三轮测试的 36 个结果，其各自 RGBA 哈希一致。

**并非所有计算都变快。** ritsu 关闭过程图时，新版约慢 0.17 秒，主要来自 JS FFT 和 PNG 读取；默认开启过程图的三个案例均更快。第一次迁移基准中，ritsu/lastTour 的过程图也曾更慢；通过限制预览大小、去除重复 PNG 编码、优化实数 FFT，才达到上表结果。保留了这批初测记录，没有删掉慢案例。

过程图现在先从原始坐标取不超过 1024 长边的预览，再绘制和归一化；大图不再为了小预览创建全尺寸 Canvas。FFT 展示不参与新的算法决策。

另测 4096×4096 图片（上述 1024 输入最近邻放大 4 倍），输出恢复到 1024×1024，旧新像素一致。单次计时：关闭过程图 **7.208 → 3.173 秒**，开启过程图 **7.301 → 3.393 秒**。这是单轮大图检查，不能当作稳定中位数或任意大图的速度承诺。

## 当前限制与维护

- JavaScript 和 Python 是两份实现。算法变更应同步对应阶段，再运行网格、像素与颜色对照；仅修改 Python 不会自动更新网页。
- PNG 的透明键转换保留原有 Pillow 行为，包括部分低位深/16 位格式的转换规则。PNG 文件编码字节不必相同，比较的是解码后的像素。
- JPEG 等格式依赖浏览器解码器；不同平台的颜色管理或编解码器可能造成像素差异。无 ImageDecoder 支持或带 EXIF 的透明 WebP 回退到 Canvas，低 alpha RGB 可能量化；PNG 始终直接读写通道。过程图字体和线条绘制也不要求与 Pillow 完全相同。
- 当前支持静态 PNG、JPEG/MPO、WebP、GIF、BMP。动画和 TIFF 不支持。超大图仍受设备内存限制，移除 Wasm 堆不等于无限内存。
- 桌面构建已改为打包同一份 JS 网站；已有发布的 exe/dmg 不会自动改变，需要重新构建发布。

网页使用与模块说明见 [web/README.md](../web/README.md)。
